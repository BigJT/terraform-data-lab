# Step 5 — Convert the list into a map
This is an important Terraform pattern. Currently we have: local.vms.vms

[
  {
    name = "vm01"
    ...
  },
  {
    name = "vm02"
    ...
  }
]

But `for_each` works particularly well with a **map keyed by something meaningful**.

Add this to `locals.tf`:

locals {

  vms = jsondecode(
    file("${path.module}/data/vms.json")
  )

  vm_map = {
    for vm in local.vms.vms :
    vm.name => vm
  }

}

terraform fmt

terraform console

local.vm_map


Now try:	keys(local.vm_map)

> keys(local.vm_map)
[
  "vm01",
  "vm02",
]

> values(local.vm_map)
[
  {
    "location" = "uksouth"
    "name" = "vm01"
    "size" = "Standard_B2s"
  },
  {
    "location" = "uksouth"
    "name" = "vm02"
    "size" = "Standard_B2s"
  },
]



# Step 6 — Replace the hard-coded VM

Now we get to the important Terraform expression.

Change main.tf from the single VM to:

resource "terraform_data" "vm" {

  for_each = local.vm_map

  input = each.value

}


So Terraform will conceptually create:

terraform_data.vm["vm01"]
terraform_data.vm["vm02"]

instead of:

terraform_data.vm

Run:

terraform fmt
terraform validate
terraform plan

You'll notice Terraform wants to **destroy the old**:
terraform_data.vm

and create:

terraform_data.vm["vm01"]
terraform_data.vm["vm02"]

That's expected because we've changed the resource addressing model.

terraform apply
